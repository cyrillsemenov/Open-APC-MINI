The Story

I have my APC Mini lying around which I've been using on and off for years. It's a nice control panel: it has 9 faders, sometimes I used it as a MIDI keyboard with a ridiculously wide range, and I've connected it to Pure Data (PD) — though I barely use it with Ableton. During all this time I wanted to get inside its brains and find out what it is capable of.

One project inspired me: craigsblackie/MPK-Mini-open. The MPK uses almost the same MCU as the APC (STM32F102RBT6), so it was almost definitely vulnerable to power-glitch readout via CTXz/stm32f1-picopwner. I connected all needed wires to an RPi Pico and dumped the firmware.

Why do we need a dump? First of all, it is a save point. Second, we might find something interesting in there. And boy there was — a hidden USB-MIDI bootloader mode, activated only by a special SysEx command! Even more counterintuitive is that on factory firmware, after sending this command, you have to physically power-cycle the APC to enter Updater mode before you can flash your own firmware onto it.

The circuit of the APC Mini is remarkably simple: just an STM32F102RBT6 MCU and a TM1629 LED driver. After initially reconstructing the stock firmware to understand every detail of the board and protocol, the firmware now runs on the open-source libopencm3 peripheral and USB-MIDI stack with key fixes and new capabilities.

What's Built & Improved

  • Soft Reboot on Updater Handshake: No physical USB power-cycle is needed when updating from this firmware — the MCU pulls the USB D+ pull-up (PA8) low, forces USB re-enumeration, and resets directly into the bootloader on the Uploader page. (Note: if you are updating from the original factory firmware for the very first time, you will need to unplug and replug the USB cable once when prompted.)
  • Smooth 7-bit & 14-bit Faders: On stock firmware, the faders jump multiple values and make it hard to dial in an exact MIDI CC value even within the 0–127 range. The ADC filter and hysteresis now track single-step 7-bit MIDI CC cleanly alongside 14-bit high-resolution values (0–16383).
  • Simultaneous USB-MIDI + Monome serialosc: Runs a composite USB device providing class-compliant USB-MIDI (plus Ableton Live Intro 0x60) alongside a USB CDC-ACM Monome serialosc / norns (mext v4) 8×8 varibright grid and 3 tilt banks mapped to the 9 faders. Active modes, 4 color palettes, and 4 TM1629 brightness steps can be toggled live on Config / Debug.
  • On-Chip Lua Co-Processor: Write sequencers and generative scripts directly inside the APC Mini. An in-browser Rust + full_moon WASM compiler turns a Lua 5.4 subset into compact LUA1 stack bytecode (with cooperative coroutines and non-destructive LED overlays), uploaded to live RAM or Flash (0x08008000) from the Script page — see the Scripting Guide.
  • SWD-Less Telemetry & Post-Mortem Black-Box: Read live MCU telemetry, peek any 32-bit address, and inspect persistent crash logs saved to Flash Page 30 (0x08007800) with ELF symbol resolution on Config / Debug.

Source Code

Source code, firmware releases, Unicorn emulator tests, CLI tools, and example Lua scripts are hosted on GitHub: github.com/cyrillsemenov/Open-APC-MINI.

Troubleshooting & Fallback: If something goes wrong, you can flash v0.2.1 on the Uploader page — it is just the fixed USB-MIDI firmware (soft reboot + smooth faders) without serialosc or the Lua VM. Please capture your telemetry & crash log on Config / Debug (Read Telemetry & Crash Log → Copy Markdown Report) and file an issue on GitHub.

Everyone is welcome to contribute — open an issue or PR on GitHub!

Important Notice for Custom Hardware & License

The default USB VID:PID (0x09E8:0x0028) and vendor strings are configured strictly for interoperability on genuine retail Akai APC Mini hardware. If you build or adapt this firmware for any non-Akai or custom hardware target, please override USB_VID, USB_PID, and USB_STRING_VENDOR (for example via pid.codes).
